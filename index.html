Understand the pressure-drop problem

What you are doing: getting to know the engineering problem before modelling it. Why it matters: knowing the inputs, the target and the expected physical trends helps you judge whether a model is sensible. What to look for: the units, the range of the data, and that this is a synthetic demonstration.
Use a different example

The pressure-drop problem is the main engineering example. A generic nonlinear dataset is also available purely as a mathematical demonstration.

Choose an approach

What you are doing: deciding how much flexibility the tool should use to learn the relationship. Why it matters: a simple trend is easy to read, while a flexible relationship can fit curved, nonlinear behaviour. What to look for: start simple, then try a more flexible approach and see whether it does better.

The simple trend is a good starting point. Pressure drop depends on the inputs in a curved, nonlinear way, so a more flexible relationship often fits it better. The trade-off is that a very flexible model can overfit — following the training data too closely and generalising worse to new conditions. A more complex model is not automatically more accurate or more suitable for engineering use. On small tabular datasets like this one, a neural network may not beat a well-tuned tree-based method.

What do these model names mean?
  • Linear Regression learns a weighted relationship: each input is multiplied by a number and the results are added up. Easy to interpret, but it may struggle with nonlinearity.
  • Decision Tree divides the input conditions into regions and predicts a value for each. It captures nonlinear behaviour, but a deep tree may overfit.
  • Random Forest combines many trees for a more stable prediction. It is less transparent than a single relationship and may extrapolate poorly beyond the data.
  • Neural network combines layers of simple units to learn nonlinear relationships. It is flexible and powerful, but needs its inputs put on a common scale, has more settings to choose, trains more slowly, and can overfit small datasets. It is offered here as an advanced option, not the default.
Network size

The inputs are automatically put on a common scale before training (the network needs this), and predictions are converted back to kPa, so the errors and charts stay in real pressure units. You do not need to configure any of this.

Interpret the engineering meaning

What you are doing: reading a plain-language summary of what the model learned. Why it matters: metrics and predictions only help if you know what they mean in engineering terms. What to look for: sensible physical trends, errors in kPa, and honest limits.
Important: good test performance does not guarantee safe extrapolation. Predictions outside the range of the training data — or for different fluids, geometries or flow conditions — can be unreliable. This is a synthetic demonstration, not a validated engineering result, and it does not replace engineering judgement.

Reproduce the pressure-drop workflow in Python

You have used the browser Explore mode to predict the pressure drop of a fluid flowing through a pipe. This guided Jupyter notebook reproduces the same activity in Python, so you can read, run and change the code behind it — the same dataset, the same five inputs and target, the same fixed random seed (42) and the same three models.

What you will do: load the dataset with pandas, split it reproducibly, fit Linear Regression, a Decision Tree and a Random Forest with scikit-learn, compare them with RMSE and R² in kPa, plot actual vs predicted, and interpret the result like an engineer (trend checks, plausibility and an extrapolation warning). No prior machine-learning experience is assumed; about 30–45 minutes.

Open in Google Colab

What the notebook covers

  • The pressure-drop problem in plain engineering language, with the expected physical trends.
  • Loading and inspecting the dataset; a reproducible train/test split with a fixed seed.
  • Fitting and comparing Linear Regression, a Decision Tree and a Random Forest.

Numbers will differ slightly from the browser — that is expected. The notebook uses scikit-learn and its own random split, while Explore uses its own in-browser model code, so the exact figures are not identical. About Engineering ML Studio

Engineering ML Studio is a browser-based tool for exploring, understanding and applying machine-learning regression to engineering data. It is aimed at engineers rather than machine-learning specialists.

  • All calculations run locally in your browser; data you load is not sent to any application server.
  • It is intended for learning, exploration and small engineering projects.
  • It is not a validated safety-critical analysis tool. Always independently verify any output before relying on it.

What does a prediction interval mean?

A prediction interval gives a range of plausible values for an individual prediction. For example, a 90% prediction interval is designed to contain the actual value for approximately 90% of comparable future observations, under the method's assumptions. A wider interval indicates greater predictive uncertainty.

What the data-quality assistant checks

The assistant runs local checks when the target or selected features change. It flags duplicate rows, missing values, constant or near-constant columns, ID-like features, high-cardinality categories, missing target values, features equal to the target, and extremely high numeric correlation with the target.

Severity: critical findings can invalidate fitting or interpretation; warnings need review; information items explain workflow state. These checks do not verify units, scientific plausibility, sampling representativeness, causal validity, or every form of target leakage.
